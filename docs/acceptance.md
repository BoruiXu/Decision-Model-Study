## 验收中发现、尚未处理的问题

1. **LoRA 合并精度**：40 步得到的 ΔW 很小，在 bf16 下与 W 相加时会被舍入掉一部分。要做到精确，合并结果只能存成 fp32；否则就要放宽容差，或者只报告差异、不判失败。
2. **忙时排不了队**：resolve 按卡**当前**的空闲显存判断是否可行，机器忙的时候连 resolve 都过不了。验收时是在 harness 外面加了一个重试脚本，每 5 分钟 resolve 一次。
3. **门没过的 run 不列删除候选**：这是之前标记过的已知问题。A7 的 checkpoint 无法用 `ojh cleanup` 清理。
4. **skill 待补充**（A6 的 agent 反馈）：
   - 没有写 `max_steps` 短跑怎么配，也没有短跑示例；
   - `ojh note` 只输出一个 `1`；
   - RUN_CARD 里有两种 sha256（源文件和 prepared 之后的子集），没有说明区别；
   - 题数有 report（194/194）和 select（191/189）两种口径，容易混淆。
5. **评测间隔按完整 epoch 计算**：设置了 `max_steps` 的短跑，中途只会评测一次。
